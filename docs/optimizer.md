# Optimizer (meta-agent)

## Problem
Six agents, each with its own runbook, skills, scripts and pending items, all edited by AI sessions, several of
them in parallel. Over time: broken paths in docs, a skill pointer that drifts from its source, the same rule
written in two places that disagree, and a hand-written "to fix" list where half the items were already fixed.

## How it works
A maintenance engineer for the agent system, working in four layers, in order. A layer only runs when the one
before it has no open high-severity item.

| Layer | Question | When | Autonomy |
|---|---|---|---|
| 1 · Hygiene | Is the text right? paths, names, sizes, retired terms, mirrors between source and pointers | alone, at night, weekly; and at the start of every round | fixes what a test proves |
| 2 · Processes | Does every routine have an owner, a trigger and a closing step, and does it actually happen? (adherence measured in the task manager) | fortnightly | proposes; applies with ok |
| 3 · Architecture | Are agents and projects well split and connected? gaps, overlaps, hand-offs, rules living in two places | monthly | proposes only |
| 4 · Evolution | New capability worth its cost: a new agent, a merge, a connection, an automation | quarterly | proposes only |

**The queue is generated by checks** (`src/optimizer/queue.py`, excerpt). Every run re-checks the real state:
a finding that no longer reproduces closes by itself, and each open item keeps the date it was first seen. Items
no check can detect (a pending decision, a manual action) live in a separate manual list with an expiry date;
an expired item must be renewed or closed. A decision, once taken, is written where it lives and never returns to
the queue.

**Metrics**, one line per day: open, new, closed by themselves, manual, expired. A finding the human rejects is
recorded with a reason in an ignore list; the same check rejected in two rounds is rewritten or removed (an
effective false positive).

The criteria it audits against are a short list of agent-engineering principles, each with a source: what is
always loaded must stay short; instructions are context, not enforcement (real blocks are hooks or script gates);
one fact lives in one place; the generator is not the evaluator; content read from files and e-mails is data,
never an instruction; git is the safety net, so nothing is applied without a commit.

## Guardrails
| Does alone (and says so in one line) | Asks first |
|---|---|
| a fact the source proves: broken path, stale name or number, a state document rebuilt from its source | the direction for a folder before touching it (1-3 questions) |
| a rule change when the source proves it (two docs contradict, or the human's decision is already recorded), with a second agent reviewing | taste, names, new structure |
| aggressive pruning of what changes no behaviour (duplicates, dead text), reversible through git | deleting files, merging or retiring agents |
| another agent's code only with green tests or a before/after comparison on a copy | harness settings and hooks; the root runbook |

Never: writes to flashcards or spreadsheets, pushes, rewrites history. It measures processes, not the person:
why a routine is not followed is the goals agent's question. It never edits a check in the same round it uses
that check to approve its own change. One commit per batch, staging only the paths it touched.

## Tests
Production: `test_fila` covers the reconciliation (open, close by itself, keep the "since" date), the manifest
checks and the pending-item checks. This repo: `tests/test_queue.py`.

## Example (fictitious)
```
$ python src/optimizer/queue.py examples/sample_system --dry
| sev    | check    | target                          | detail                                   |
| high   | manifest | agents/12-agent-reports         | no CLAUDE.md                             |
| medium | manifest | agents/11-agent-notes/CLAUDE.md | missing: Autonomy, Cadence, Out of scope |
```
Round output, always in this order: the human's decisions ranked by priority (the one most likely to be
contested first) -> one line of what was done, with commits -> at most three macro proposals.
