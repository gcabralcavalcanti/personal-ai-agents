# Goals & behavior analysis system

> Architecture only. The production agent works on private material (journal, habits, goals); none of it is
> in this repository. Every example below is fictitious.

## Problem
Quarterly goals written once and never measured; a habit tracker and a task manager full of data nobody
reads against the goals; and self-assessment that swings with mood. The question "am I on track, and if not,
why?" needs the subjective story and the objective data side by side.

## How it works
One agent, three modes, chosen from the request (ambiguous request: it asks).

| Mode | What it does | Writes |
|---|---|---|
| Conversation (default) | critical reading of a pattern: crosses what the person says with what the data shows | a dated entry in its own case file (analysis lives there, nowhere else) |
| Goals, level 1 | questions about the active goals and key results; no ritual | nothing |
| Goals, level 2 | the quarterly ritual: score the quarter that ends, full internal scan, external benchmarks, compose the new quarter | the goals file and the goals history, only after the person approves the text |
| Memoir | hands over to the [memoir scribe](memoir-scribe.md) | the memoir, under that module's rules |

**Pre-flight proportional to the request.** A full analysis reads everything first: the live task manager
(what was actually done, what was postponed), the habit pipeline's weekly bulletin (execution days per goal
area, current "phase"), the goals file and the case file. A point question ("what phase am I in?") reads only
the one source it needs. Asking the person a fact the data already shows counts as a pre-flight failure.

**The divergence is the finding.** The highest-value output is the gap between the felt score and the
measured one for the same period (fictitious: "career area: felt 3/10, measured 7/10 days with execution").

**Called by another agent.** Other agents can ask it one question mid-conversation (e.g. the career agent
routes "why do I freeze before applying?" here). It answers that question only, from a short pre-flight, and
the calling agent keeps the conversation.

## Goal format (what level 2 writes)
- Three layers: **core** goals (2-4 key results each), **maintenance** (one line, no number), **calendar** (things
  that are only dates).
- Every key result is either an **artifact** (exists or not: measuring is looking) or a **series** (a rate from a flow
  that already runs on its own). A key result that needs a new manual counter is rewritten as an artifact.
- Each key result declares its source: `[artifact]`, `[habit app]`, `[task manager auto]` or `[label count]`.
  Forbidden as a source: the task manager's completion rate (tasks get closed to be rescheduled).
- **Anti-rot**: a key result never names a folder, deck or project label; if renaming a folder would break it, it is
  badly written.
- **Targets come from the measured base**, not from the wish: far from the target -> a monthly step, base written
  next to the target.
- **No goal without a task**: the agent proposes the chained tasks as one batch; the Secretary agent writes them
  through its validation gate, after the person's ok. A key result never becomes a task by itself.

## Guardrails
| Rule | Why |
|---|---|
| Writes the goals files only after the person approves the exact text | goals are the person's decision |
| The dashboard is generated by a script from the goals files, never edited by hand | one source of truth |
| Never writes to the task manager or the flashcards; proposes a batch to the agents that own them | single writer per system |
| Reads the "phase" computed by the habits agent; never recalculates it | one fact, one place |
| The phase changes the tone and the ambition of a proposal, never blocks anything | indicator, not a gate |
| External benchmarks inform; they never override the person's own criteria | the agent researches, the person decides |
| Engineering rules for agents are not its business (that is the Optimizer's) | clear boundaries |

```
> how is the quarter going?
Measured (task manager + habit app, last 4 weeks): study area 18/28 days with execution; sleep before 23:30 9/28.
Felt (your weekly review): study 4/10, sleep 7/10.
Reading: the gap is the opposite of what you feel - study is on track, sleep is not.
Key result "finish chapter 2 draft" [artifact]: not found in the project folder.
Proposal (needs your ok): move the sleep key result to a monthly step (base 9/28 -> 14/28 in November).
```
